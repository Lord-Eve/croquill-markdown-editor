# 官方 Typora 体验对照与验收记录

日期：2026-10-27。唯一产品体验参照：[官方 Typora](https://typora.io/)，以及 `support.typora.io` 官方支持文档。Typora Next 不参与外观、排版或交互验收。

本文中的“已实现”仅表示当前源码有对应实现；实测结果需单独填写。编辑器框架自带功能、单元测试通过、浏览器模拟事件均不等于官方 Typora 行为一致或真实中文输入法验收通过。

这些参数来自该本机 Typora 安装的主题文件，属于样式源码证据；实际屏幕像素仍受窗口尺寸、缩放与字体影响。

## 验收记录的写法

- **源码实现**：说明代码已接入哪个动作，不能写成桌面验收通过。
- **自动化结果**：记录断言与运行环境，尤其区分注入中文字符串、模拟 composition 事件和真实 IME 选词。
- **实际桌面结果**：记录真实 Windows 窗口、原生打开保存与文件内容核对。
- **与官方一致性**：只有同一操作已在两边直接观察，才填写一致；不一致时明确光标、标记显隐、菜单、滚动或排版的具体差距。

内容保真、写入失败不丢稿、UTF-8/BOM/换行与手动保存属于本项目独立的文件可靠性验收项，仍按用户要求验证；不需要以 Typora 内部文件实现来替代这些断言。

## 按解析结果放宽源码保护：第一批（2026-10-28）

本轮只解决含特殊语法的文档无法富编辑的问题。HTML 判断来自 remark 的实际 `html` 节点，不用尖括号正则猜测标签；代码与普通比较符号不纳入 HTML 原文块。扩展语法依照解析后的文字 / 节点识别，包含这些语法的顶层段落、标题、列表或引用作为一个原文块保存，其余正文仍可编辑。

### 逐类保真结果

下表“放行”表示整篇可以进入所见即所得模式，并非已实现该语法的 Typora 式渲染。每个放行样本均通过实际 Edge 中的生产 Crepe 内核执行“打开 → 编辑另一段 → DocumentSession 保存”，断言目标原文完整出现一次、字符及原始换行不变、结构等价；还验证未编辑保存、源码往返和撤销。保存端口在测试中使用内存，不冒充本轮 Windows 原生文件保存验收。

| 类别 / 样本 | 放行 / 仍保护 | 当前呈现与依据 |
| --- | --- | --- |
| `a<b`、`x > y` | 放行，普通正文 | AST 不含 HTML 节点，不生成原文块，不再误判 |
| `Promise<string>` | 放行 | CommonMark 将 `<string>` 解析为 HTML，所在段落以原文块完整保留 |
| 行内 `<br>`、`<span>`、`<kbd>` | 放行 | 含 HTML 的整个段落原样保留；带属性空格、内嵌 Markdown 的样本也通过 |

| `:::` 容器 | 放行 | 开闭标记及中间段落一起保留，包括内部空行 |
| `{#id}` / `{.class}` 属性 | 放行 | 含属性的标题或段落完整保留，暂不应用属性 |

### 图片处理的选择与官方依据

官方 [Images / 相对路径](https://support.typora.io/Images/#relative-path-to-current-filefolder-default-behavior) 说明相对路径以当前 `.md` 所在目录为基准；[Copy Image](https://support.typora.io/Images/#copy-image) 和 Copy All Images 说明复制后更新引用、保留原图。该页没有明确规定“另存为必须自动复制附件目录”，本轮没有将这种猜测写成本机 Typora 实测结论。

采用**改写路径，保留原文件**：同盘生成相对新文档目录、仍指向原图的路径，跨盘改为本地 `file:///`；仍能解析到同一原图的路径保持原写法。新文档继续依赖原附件目录，没有额外复制附件。先验证所有有关图片，再执行原安全写入，任一检查失败都不写副本、不切换当前文档，不移动或删除原图。

源文档或目标文档存在文件链接时，按安全写入器和图片读取器实际解析到的文件位置确定基准，避免按链接所在目录算出错误路径；普通源文件已丢失时仍可根据原目录另存内存正文。另有实际文件系统回归覆盖源 / 目标文件链接、目标附件同名但内容不同、中文及空格编码、缺图失败和原图保留。

修改范围只限真实 Markdown 图片目的地址、被图片使用的引用定义、HTML `img src` 的路径部分；保留原来的 alt、标题、查询参数 / 片段、代码、注释、普通链接、元数据、BOM 和换行。含图片的 HTML 仍按已有源码保护规则显示，不新增 HTML 渲染；引用式文档沿用已有的结构保护，可能进入源码模式，本轮不放宽它的渲染保护。改写了图片地址、或首次为含本地图片的草稿确定路径时重新加载来源，避免显示旧缓存；普通保存不重建编辑器。
