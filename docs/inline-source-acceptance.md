# 行内标记随光标显隐：实现与验收

日期：2026-11-13（机器时间）。分支：`inline-source`，三段完成、真实输入法实测通过后合并到 main。做法和原型见 `docs/inline-source-spike.md`；Typora 的对照依据是 `docs/typora-acceptance.md` 里 2026-11-10 的实测记录。

## 做了什么

三段都已完成。

1. **读入、保存、显示。** 打开文档时，加粗、斜体、删除线、行内代码、高亮以及反斜杠转义、实体都保留源码字符；保存时原样写出。显示层把标记藏起来、给内容加样式，光标碰到某一处时显示它的标记。
2. **命令与输入。** Ctrl+B / Ctrl+I / Ctrl+Shift+X、格式菜单的行内代码和高亮改为增删标记字符；格式中间按回车两段都保持格式；输入链接写法即时成为链接；网页粘贴的格式写成 Markdown 标记。
3. **周边与验收。** 查找替换、表格局部保存、目录和大纲、脚注预览都按新模型核对；测了长文性能；在真实窗口验收。

代码在 `src/inline-source.ts`（语法识别、行首转义）、`src/inline-source-markdown.ts`（读入与保存）、`src/inline-source-view.ts`（显示、命令、回车、链接输入）。

## 与 Typora 记录逐条对照（浏览器回归 + 真实窗口）

| Typora 记录 | Croquill |
| --- | --- |
| 点进加粗文字，两侧出现灰色 `**`；斜体、行内代码、删除线同理，同一时刻只显示光标所在那一处 | 一致；高亮 `==` 同样处理 |
| 方向键：文字末尾 → 两个 `*` 之间 → `**` 之后，标记都保持显示；再右移一格隐藏 | 逐格一致 |
| 在结尾两个 `*` 之间退格，立刻显示为字面 `*` 加斜体 | 一致 |
| Ctrl+Z 恢复加粗并把光标放回原处 | 一致，光标离开后再撤销也成立 |

Typora 当时没测、这里按最直观方式实现的：嵌套格式内外两层标记都显示；有选区时，选区碰到的每一处都显示标记。

## 这轮顺带查出并修掉的老问题

- **CRLF 文档只要段内有软换行就进源码保护。** 真实窗口验收时发现，在 main（0.4.0）上用同样内容复现，与本次改动无关。原因是结构等价判断把值里的 `\r\n` 和 `\n` 当成不同内容。已修，加了单元和应用级回归。
- **源码保护能被 Ctrl+/ 绕开。** 进了保护的文档切换模式后会回到所见即所得。已修，加了回归。
- **测试服务器固定用 5173 端口。** 本机代理程序占用该端口时全部浏览器测试无法启动。改为向系统申请空闲端口。

之前的 CRLF 用例没暴露第一个问题，是因为测试辅助函数 `focusApp` 会主动切回所见即所得，恰好绕开了保护；新测试在调用它之前先断言文档自己是以所见即所得打开的。

## 真实拼音输入法（最终 exe，真实窗口）

本机系统输入法处于中文状态，通过系统级的真实按键逐个输入拼音字母，候选窗口正常弹出，按空格上屏首选词。测试文档 `前文 **加粗文字** 中间 *斜体文字* 结尾`，BOM + CRLF，放在已忽略的 `test-results/inline-source/`。

| 光标位置 | 输入 | 结果 |
| --- | --- | --- |
| 加粗文字中间 | zhongwen + 空格 | “中文”进入加粗文字中间，仍是加粗，标题栏出现未保存圆点 |
| 紧贴开标记 `**` 之后 | ni + 空格 | “你”成为加粗内容的第一个字 |
| 紧贴闭标记 `**` 之后 | shi + 空格 | “是”落在加粗之外、紧跟在 `**` 后，不加粗 |
| 闭标记后隔一个空格 | hao + 空格 | “好”落在空格之后，不加粗；Ctrl+Z 一次撤掉整个字，Ctrl+Y 恢复 |
| 加粗文字中间（标记显示时） | de + 空格 | “的”进入加粗文字 |

保存后磁盘内容为 `前文 **你加中文粗的文字**是 好中间 *斜体文字* 结尾`，与预期逐字节一致（含 BOM 和 CRLF）。

这款输入法组词时把拼音显示在自己的候选窗口里，不写进编辑区，所以“紧贴标记的拼音显示为灰色”这一现象在本机没有出现；它只会出现在把拼音直接写进编辑区的输入法上（浏览器调试接口模拟的就是这种）。候选窗口属于另一个程序，截图里被遮住，看不到候选词内容；结论依据是上屏后的文字和磁盘字节。

## 这轮真实按键测试查出并修掉的问题

**从右边用左方向键走向一处隐藏的标记，光标会一步跳过 `**`，直接落到文字末尾。** 向右走没有这个问题，所以此前与 Typora 的对照（只记录了向右）是通过的；先前的回归只检查“每次按键光标都移动”，没有检查落点。另外，两次按键间隔极短时，第二次按键会抢在标记显示出来之前，同样越过标记。

修复：方向键按下时先让编辑器读入上一次按键造成的光标位置；当这一步会碰到一处标记还隐藏着的格式时，由编辑器自己走这一格。标记显示出来之后仍用浏览器自己的移动。新增回归覆盖向左、向右各 1～4 次按键，间隔 0 毫秒和 30 毫秒，逐次核对落点。
## 已知的不足

- **组词时紧贴标记的拼音显示为灰色。** 只在把拼音直接写进编辑区的输入法上出现，只影响上屏前的外观；本机输入法没有这个现象。试过在光标处放一个定位用的空节点来纠正，结果浏览器会丢掉组词状态（拼音留在原地、汉字追加在后面），所以没有采用；这条约束写进了 `AGENTS.md`。
- **复制到 Word 等富文本程序时带着标记字符。** 在 Croquill 内部复制粘贴是原样往返。
- **输入的行内 HTML、裸网址**要到重新打开文档后才显示为原文片段 / 链接。输入时它们是普通文字，保存的内容没有问题。
- **行首 Delete、已有标题行首输入 `# ` 加空格**等标题细节仍是上一轮记录的状态，未动。
- 表格单元格里行内代码中的 `\|` 会按源码原样显示反斜杠。

## 行为变化（都来自“文档里就是源码”）

- 删掉加粗或高亮里的全部文字，标记字符会作为普通文字留下。
- 在高亮中间输入 `==`，高亮在那里结束。
- 输入 `*`、`_`、反引号等字符不再被保存成带反斜杠的形式；它们是不是格式，取决于前后文，屏幕上立刻可见，和保存后重新打开的结果一致。
- 光标在段首时，位于该段开头的 `**` 之前。
