# 保存后的焦点、撤销与重做验收

日期：2026-11-09。问题基线：`main@1c7b930`。

## 判断验证

先写真实应用浏览器测试，再改生产代码。只模拟 Tauri 的文件系统、原生对话框边界；编辑器、全局快捷键和 `run()` 都使用生产代码。

保存需要跨浏览器帧：文件写入 mock 保持 pending，等待编辑区的 inert 生效后才放行。立即返回的 mock 会在浏览器处理失焦之前结束保存，掩盖缺陷。新测试初次冷启动超过默认 5 秒，因此本文件测试限时设为 30 秒；没有改动全局测试配置。

- 修改前，富文本与源码的 `document.activeElement` 在保存后均为 `BODY`；两项焦点回归失败。
- 修改前，手动 `surface.focus()` 后立即 Ctrl+Z，两种模式都能撤回粘贴：两项诊断通过，证明历史仍在。
- 同路径保存没有 `surface.load()`，也没有调用替换功能的 `closeHistory` / `isolateHistory`。
- 根因是 `run()` 的 inert 使编辑器失焦；原有结束路径只解锁，没有恢复焦点。打开、新建、切换模式时的内部聚焦也可能发生在 inert 期间，浏览器无法执行它。

## 修复与语义

`MarkdownSurface.deferFocus()` 在进入 inert 前记录编辑器是否持有焦点，并收集操作期间的显式聚焦请求；`run()` 解除 inert 后再执行。恢复使用编辑器模型中保留的选区，不新增撤销步骤，不把插图后光标移回旧位置。已打开的 dialog / popover、操作期间接手的其他控件优先持有焦点。

普通保存不清空历史。撤销、重做均能跨保存点；内容回到当前保存版本时，标题圆点和“未保存”标记消失。另存为没有改写正文时继续保留历史；另存为改写图片路径需要重新载入、重新打开文档时，允许清空历史。

## 浏览器回归范围

新增 `tests/app-operation-focus.test.ts`：

- 两种模式：保存期间 activeElement 变为 BODY；人工聚焦后历史仍可撤销；修复后保存完成即自动恢复焦点、正向选区和 DOM 所选文字。
- 两种模式 × LF / CRLF × 有无 UTF-8 BOM：编辑 → 保存 → 撤销 → 保存，原文逐字节恢复；重做 → 保存，编辑后内容逐字节恢复。对原生写入边界收到的文本、BOM 参数重建 UTF-8 字节并比较；不以字符串包含或写入次数代替内容断言。
- 保存后撤销变脏、重做到已保存版本自动变干净；再次保存原文后，重做变脏并可保存。
- 保存后的第一次点击能把光标放到点击位置并立即插入文字；连续 Ctrl+S、保存中排队的 Ctrl+S、BODY 焦点下 Ctrl+S 都实际送到写入边界。
- 打开文件夹、插图、另存为、打开文件：原生对话框延迟返回后恢复焦点；取消这些对话框也能继续编辑。新建、切换模式、另存为图片路径改写后的新编辑器能获得焦点；重载后撤销不回到上一个文档。
- 原焦点在侧栏时，菜单插图或拖入图片仍在插入完成后主动聚焦正文；显式聚焦请求同样经过 `run()` 的解除锁定流程，不在外部无条件抢焦点。
- 保存失败对话框期间不抢焦点，关闭后回到编辑器；dialog / popover / 侧栏在操作中取得焦点时不抢回；从文件树、查找、菜单保存不强行聚焦正文。

“Ctrl+S 偶尔不生效”没有复现为独立的快捷键派发缺陷：BODY 中仍可保存，保存中的再次请求仍会排队。窗口级快捷键路径保持原实现。“第一次点击只取得焦点”未单独复现；保存后的失焦已修复，首次点击定位与立即输入有两种模式的回归覆盖。
