# 行内标记随光标显隐：技术验证

日期：2026-11-13。目标：按项目所有者的决定，做到和官方 Typora 一样——光标进入加粗等格式时显示标记，光标能走进标记，标记能直接编辑。对照依据是 `docs/typora-acceptance.md` 里 2026-11-10 的实测记录。

## 结论

可行。采用“源码常驻、标记隐藏”的做法：行内格式不再转换成编辑器内部的格式标记，`**加粗**` 这几个字符原样留在文档里；平时用显示层把 `**` 藏起来并把中间的字画成粗体，光标碰到这一段时把标记显示出来。

没有采用“光标进入时把这段临时变回原文、离开时再变回去”的做法。原因：它每次移动光标都要改动文档，撤销历史会对不上（推演结果：在标记里做过的修改，离开后按 Ctrl+Z 会撤到别处去），保存时还要处理“正展开着的一段”，三条底线都要额外设防。新做法移动光标不改文档，这些问题不存在。

## 原型

`tests/spike/inline.html`、`tests/spike/inline-spike.ts`：一个只有段落和文字的最小 ProseMirror 编辑器，行内解析用项目已有的 remark，约 100 行。它不是产品代码，不随 `npm test` 运行；要重跑，把 `tests/spike/inline-spike.manual.ts` 临时改名为 `inline-spike.test.ts` 后执行 `npx vitest run tests/spike/inline-spike.test.ts`。

运行环境是测试用的 Edge（和 WebView2 同一内核），按键是真实键盘事件。

## 已看到的问题

- 组词期间，如果光标紧贴在标记后面，正在输入的拼音字母会暂时显示成标记的灰色，上屏后恢复正常。需要在正式实现里处理。
- 模拟组词不能代替真实拼音输入法，正式实现后要由项目所有者上手测。

## 接入现有编辑器要改什么

原型只证明了手感和撤销。接进 Croquill 还要做这些：

1. **读入。** 现在打开文档时，加粗、斜体、删除线、行内代码、高亮会被转成内部格式标记。要改成保留这段源码原样作为文字。项目里行内 HTML 片段已经是“按源文件位置原样截取”，有现成做法可循。
2. **保存。** 这些文字保存时要原样写出，不能被加上反斜杠转义。这一点同时改善“保留原有写法”：行内格式的写法从此逐字符保留。
3. **段首安全。** 原样写出的文字如果以 `# `、`- `、`1. `、`> ` 开头，重新打开会变成标题或列表。保存前要检查并只在这种情况下转义。
4. **显示。** 把原型的显示层搬进来，支持标题、列表、引用、表格单元格；按段缓存解析结果，避免长文每次移动光标都全文解析。
5. **命令。** Ctrl+B / Ctrl+I 等要从“切换格式标记”改成“在文字两侧加上或去掉标记字符”；关闭内核自带的“输入 `**x**` 自动转成格式”的规则；从网页粘贴进来的粗体要转成源码写法。
6. **转义和实体。** `\*` 里的反斜杠、`&amp;` 这类写法平时也应隐藏、光标靠近时显示，用同一套机制。
7. **高亮 `==`。** 现有高亮是自写的解析，要并入同一套显示层。
8. **受影响的现有功能。** 查找替换的位置换算、表格局部保存、脚注与高亮混排、源码保护判断。直接依赖格式标记 DOM 的现有测试约 17 处，分布在 3 个文件。

链接（路线图下一项“链接原位编辑”）可以用同一套机制做，这次先不动。

## 建议的做法

- 这是到目前为止最大的一次改动，中间状态不能发版，建议在分支上做，不直接改 main；需要 CI 时用 workflow_dispatch 指定分支。
- 分三段，每段结束向项目所有者汇报：
  1. 读入、保存、显示：打开和保存逐字节不变，四种格式加高亮能显隐，光标能走进标记，标记可编辑。
  2. 命令、输入和粘贴：快捷键、逐字输入、网页粘贴、转义显示。
  3. 验收：真实拼音输入法、长文性能、表格和查找替换，全部现有测试通过。
