## 1. 目标

现状：

- 含 `[[双链]]`、`![[嵌入]]`、`:::` 容器、`{#id}` / `{.class}` 属性、行尾 `^abc123` 块引用标识的顶层块，整块变成灰色等宽原文块，只能在源码模式里改。
- 列表项直接以标题开头（`- # a`、`1. ## a`）时，往返会在标题前生成空段落（输出 `<br />`），结构检查失败，**整篇文档**进入源码保护。

做完后（与 Typora 实测一致）：

1. 双链、容器、段落里的属性、块引用标识作为**普通文字**显示，可以直接编辑。不渲染成链接，不嵌入图片，不套容器样式。
2. 标题里的属性 `{#id}`、`{.cls}`、`{#a .b}` 平时隐藏；光标在这个标题里时以灰色标记样式显示，可以直接编辑。
3. 列表项里的标题直接显示成对应级别的标题，可以编辑、输入中文；保存不多出空段落或 `<br />`。
4. 未编辑的文档保存后与原文逐字节一致；编辑后只改动编辑过的字。

## 2. 范围

**做：** 源码保护判断、标题属性的显示层、列表项允许以标题开头、可见文字、切换定位、测试、样本和文档。

**不做：**

- 双链的点击跳转、`![[图片]]` 嵌入显示、双链补全。
- 用 `{#id}` 作为文内跳转目标，或改变现有标题 id 的生成方式。
- 给 `{.class}` 应用任何样式。
- `:::` 容器的任何特殊外观。
- 同一个顶层块里还有本单以外的保护类别（不能渲染的 HTML、行内 HTML 边界、格式不对的提示块、引用式链接等）时，这个块照旧整块保护。
- 任务列表项以标题开头（`- [ ] # a`）。保持现状即可，不要求支持。
- 升级或新增依赖；版本号、标签、发版。

## 4. 设计

### 4.1 双链、容器、段落属性、块引用标识：普通文字

- 从保护类别里去掉“双链”“容器”“属性”“块引用标识”，并去掉 `:::` 容器的跨块合并。
- 这些写法按 remark 的实际解析结果进入所见即所得：`[[a]]`、`![[a]]`、`[[a|b]]` 是普通文字；`::: warning` 与后面的行是普通段落（中间有空行就是几个段落）；`{.note}`、`^abc123` 是普通文字。
- 保存时文字原样写出：不得把 `[`、`]`、`!`、`:`、`{`、`}`、`^`、`|` 转义。行首规则沿用 `guardLineStart`，不要恢复全局转义。
- 如果 remark 把其中某一部分解析成了别的结构（例如文档里另有定义 `[a]: url`，使 `[[a]]` 里的 `[a]` 成为引用式链接），按那个结构现有的规则处理，不另做特殊判断。
- 表格单元格、引用、列表项里的这些写法同样成立。

### 4.2 标题里的属性

- 范围：ATX 和 Setext 标题文字里，形如 `{` + 一个或多个以空白分隔的 `#名字` 或 `.名字` + `}` 的片段，出现在标题末尾或中间都算。`名字` 由字母、数字、`-`、`_`、中文组成。`{key=value}` 等其他花括号内容不算，按普通文字。
- 表示方式：属性就是标题里的源码文字，**不新建节点或 mark**，只用装饰隐藏或显示，与现有 `**` 标记相同。
- 光标不在这个标题里：属性片段隐藏（包括它前面紧挨的一个空格，使标题末尾不留空隙；标题中间的属性只隐藏花括号片段本身）。
- 光标在这个标题里的任何位置：这个标题的所有属性片段以现有标记的灰色样式显示。其他标题不展开。
- 方向键、Home / End、Backspace / Delete 跨过隐藏片段的行为，与现有隐藏的 Markdown 标记一致；不得让一次按键只删掉半个属性。
- `AGENTS.md` 的要求依然有效：光标所在位置不能放额外的 DOM 节点；输入法组词期间不得改动显隐状态导致组词中断。
- 在标题里打完 `}` 后立即按上面的规则显隐，不用重新打开文档。
- 段落、列表项、表格里的花括号属性**不隐藏**，按 4.1 当普通文字（Typora 实测如此）。

### 4.3 列表项里的标题

- 让列表项可以直接以标题开头。推荐做法：在 Croquill 自己的代码里扩展或覆盖 `listItemSchema` 的 `content`（例如 `(paragraph | heading) block*`），**不要修改 `node_modules`**。如果有更稳的做法也可以，在 PR 说明里讲清楚。
- 解析：`- # a`、`1. ## a`、`* ### a`、嵌套列表里的 `- ## a`、标题下一行缩进还有正文的列表项，都解析成“列表项 → 标题（→ 后续块）”，不再插入空段落。
- 保存：上述样本打开不编辑，逐字节一致；在标题里改一个字，只差这个字。列表的松紧（项之间有没有空行）、编号、符号（`-`、`*`、`+`）保持原样。
- Crepe 的列表项视图（圆点、编号、复选框）在标题开头的列表项上显示正常，不报错。
- 编辑行为：
  - 列表项标题里按 Ctrl+1～6、Ctrl+0、Ctrl+= / Ctrl+-、行首 Backspace，与普通标题规则相同；变回正文后成为这个列表项的普通段落。
  - 在列表项的普通段落开头输入 `# `，行为与普通段落开头一致。
  - 在列表项标题末尾回车：在同一个列表项里新起一段普通段落。
  - 现有列表的缩进、取消缩进、回车新建列表项、空项回车退出列表等行为，对普通列表不变。
- 大纲不列出列表项里的标题（现有 `markdownOutline()` 只取顶层标题，保持即可）。`[TOC]` 与大纲一致。
- 如果某种写法改不动、无法保证保存逐字节一致，那种写法**继续源码保护**，不能悄悄改写原文；在 PR 说明里写清楚是哪种写法、原因是什么。

### 4.4 可见文字

- `visibleText()` 以及所有用它的地方（大纲、目录 `[TOC]`、字数统计）不计入标题属性。`## 目标标题 {#custom-a}` 在大纲里显示“目标标题”。
  - 这一点与 Typora 不同（Typora 大纲会显示 `{#custom-a}`），是项目所有者确认的选择。
- 双链、容器标记、段落属性、块引用标识是普通文字，照常计入。

## 5. 测试要求

用仓库现有的单元测试和浏览器应用测试写法。

**有意改变的现有测试和样本：** 现有测试和公开样本里，凡是断言“含双链 / 容器 / 属性 / 块引用标识的块被保护”的，属于本单有意改变的行为。另有一些测试和样本只是**借用** `[[双链]]` 来制造“这块要继续保护”的情形（例如 `examples/html-block.md`、`examples/toc-footnotes.md`、`examples/highlight-alert.md`、`examples/search-replace.md` 里“混有双链，仍应保护”的块，以及 `examples/outline-position.md` 里关于 `{#overview-id}` 进入原文块保护的说明）。处理方式：

- 断言本身就是“这几种写法被保护”的：改成新预期。
- 只是借双链制造保护的：把双链换成本单之后**仍会**整块保护的写法（自己选一种，例如没闭合的行内 HTML），保持原测试的用意。
- 不得删除测试来让它通过。在 PR 说明里逐条列出改了哪些测试和样本、改动前后的断言或写法。

至少覆盖：

1. **普通文字：** `[[a]]`、`![[a]]`、`[[a|b]]`、`::: warning` 容器（有空行、无空行，LF 和 CRLF）、段落末尾 `{.note}` 和 `{#para}`、行尾 `^abc123`，分别在段落、引用、列表项、表格单元格里：打开后不是原文块；不编辑保存逐字节一致；在旁边输入一个字后只差这个字；文字里没有新增反斜杠。
2. **标题属性：** 末尾 `{#id}`、`{.cls}`、`{#a .b}`、中间 `{#mid}`、Setext 标题；光标在标题外时隐藏、在标题内时显示；只展开光标所在的标题；方向键和删除不拆开属性；在标题里逐字输入 `{#x}` 打完 `}` 后隐藏规则生效；`{key=value}` 不隐藏；段落里的 `{.note}` 不隐藏；模拟组词期间显隐不变。
3. **列表标题：** 4.3 列出的每种写法打开、不编辑保存逐字节一致；标题里输入中文、保存只差输入的字；Ctrl+0 变回段落、Ctrl+2 改级别；标题末尾回车；松散列表和紧凑列表各一例；普通列表的现有测试全部照旧通过。
4. **可见文字：** 带属性的标题在大纲里只显示文字；字数统计不计属性；列表项里的标题不进大纲。
5. **切换定位：** 标题属性前后、列表项标题里、双链和容器文字里的光标在两种模式间双向精确到字。
6. **混合：** 同一段里有双链和不能渲染的 HTML 时，整块仍按现有规则保护。

新增公开样本 `examples/wikilinks-attributes.md`：把第 4 节每种写法都放进去，每种附一句“应该看到什么”，最后写一段手动验收步骤（参照 `examples/inline-html.md` 的写法）。只用公开内容，不新增图片等私人素材。
