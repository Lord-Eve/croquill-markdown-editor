## 4. 设计

### A. 导出 HTML

1. “文件”菜单在“另存为”下面加一条分隔线和两项：“导出为 HTML…”“导出为 PDF…”。现有菜单（`src/menu.ts`）不支持子菜单，平铺即可，不要为此新做子菜单。
2. 选择后弹保存对话框：默认文件夹是文档所在文件夹，默认文件名是文档名改扩展名为 `.html`；未命名文档为 `未命名.html`。目标已存在时由系统对话框确认覆盖。
3. 导出内容：
   - 和所见即所得正文显示一致，用**当前主题**（浅色或深色）的样式，样式全部内嵌在 `<style>` 里，不引用本机文件，不联网。
   - `<html lang="zh-CN">`，`<meta charset="utf-8">`，`<title>` 是文档名（不含扩展名）。
   - 每个标题带 `id`，目录 `[TOC]` 的链接能跳到对应标题；脚注引用和定义能互相跳转。
   - 公式、代码块语法高亮、提示块、表格、任务列表、高亮、行内 HTML 显示正确。公式的字体处理方式在 PR 里说明。
   - 本地图片保持文档里原来写的路径（与 Typora 一致）；网络图片保持原地址。
   - **不能带出任何编辑痕迹**：`contenteditable`、光标、选区、专注模式的变浅、打字机模式的留白、查找高亮、左侧灰色 `#` 提示、拖放指示、占位提示、隐藏的行内标记字符（`**`、`[`、`](地址)` 等，既不能显示，也不能被复制出来）、原文保护块的编辑外壳。
   - 不输出脚本（`<script>`）。内容里的 HTML 仍按 `src/html-sanitize.ts` 的规则过滤。
4. 写文件走 `documents.rs` 的安全写入（可以直接复用 `write_document`，UTF-8 无 BOM、LF，不带版本检测）。
5. 源码模式下导出，结果与所见即所得模式下导出一致（先按当前文本生成，不要求切换模式）。
6. 导出不改变文档本身：不标记已修改，不影响撤销历史，不改光标和滚动位置。
7. 成功后用现有 `toast` 提示“已导出：文件名”，并提供“在资源管理器中显示”（可以是提示条里的按钮，用 `explorer /select,` 实现，路径作为参数传入，不能拼进命令字符串）。失败时弹窗说明原因，文档不受影响。

### B. 导出 PDF

1. 菜单位置和保存对话框同 A，默认扩展名 `.pdf`。不出现打印对话框。
2. 版式：A4 纵向，四边留白与 Typora 接近（约 2 厘米左右即可），**一律用 GitHub 浅色主题**，没有页眉页脚。
3. 内容规则同 A 第 3 条，另外：
   - 本地图片必须印出来（导出 PDF 时可以把本地图片转成内嵌数据，但不能改 HTML 导出的路径规则）；
   - 尽量不把一行文字、一行表格、一张图片、一个代码块的单行从中间切开（`break-inside: avoid` 一类规则即可，长代码块和长表格允许跨页）；
   - 宽表格、长代码行不能被截掉内容（允许换行或缩小）。
4. 实现：用 WebView2 的“打印为 PDF”（`ICoreWebView2_7::PrintToPdf`，经由已有的 `webview2-com`）。可以开一个隐藏的窗口或离屏页面加载导出用的 HTML。PDF 必须先写到目标文件夹里的临时文件，再经 `documents.rs` 原子替换到目标路径；不能让 WebView2 直接写目标文件。临时文件在成功和失败时都要清理。
5. 成功、失败提示同 A 第 7 条。导出期间编辑区不锁定；同时只允许一个导出任务，第二次点击时提示“正在导出”。

### C. 自动保存

1. “文件”菜单在“另存为”后面加“自动保存”勾选项（样式同 08 的“专注模式”），默认关闭，状态记在 `localStorage`（键名 `croquill-autosave`）。
2. 开启时：
   - 文档变脏后，停止输入约 1 秒自动保存一次；一直不停手时，距上次保存超过 5 秒也要保存一次。
   - 只保存已经有文件路径的文档；未命名文档照旧，需要手动保存。
   - 拼音组词期间不保存，组词结束后按上面的时间规则。
   - 保存经由 `session.save()`，和手动保存同一条路径，同样做版本冲突检测；同一时间最多一个保存在进行，进行中又有修改则结束后再存一次。
   - **不能用 `run()`**：不设 `inert`、不移动焦点和光标、不打断输入法、不弹“正在保存”之类的模态框。状态栏可以照常显示保存状态。
   - 保存期间继续输入的文字不能丢，也不能被标记成已保存。
3. 开启时，打开别的文件、新建、从侧栏切换文件、关闭窗口：如果当前文档有路径且有未保存修改，直接保存后继续，不再询问；保存失败则退回现在的询问对话框。未命名文档仍然询问。
4. 出错时：
   - 文件被别的程序改过或移走（版本冲突）：**不覆盖**，本文档暂停自动保存，弹出现有的冲突说明；用户手动另存为或重新打开后恢复。
   - 只读、磁盘满等其他错误：提示一次（`toast` 即可），内容保留在编辑器里，下一次修改时再试；同一错误不要每秒弹一次。
5. 打开后没有修改的文档不会被自动保存写盘（底线第 2 条）。
6. 从关闭切到开启时，如果当前文档已有未保存修改，按第 2 条的时间规则保存。

## 5. 测试要求

在现有浏览器测试和 `cargo test` 的写法上补充，至少覆盖：

- **A**：
  - 用 `examples/` 下的公开样本（至少 `typora-feel.md`、`inline-source.md`、`highlight-alert.md`、`toc-footnotes.md`、`wikilinks-attributes.md`）导出，检查：标题 `id`、`<title>`、样式内嵌、无 `<script>`、无 `contenteditable`、无隐藏标记字符（取导出页面的 `innerText` 与正文 `visibleText` 对比）、目录和脚注链接指向存在的 `id`；
  - 打开专注模式、打字机模式、查找高亮时导出，结果与关闭时相同；
  - 源码模式导出与所见即所得模式导出相同；
  - 导出前后文档字节、修改状态、撤销历史不变；
  - 浅色、深色主题各导出一次，样式随主题变化。
- **B**：Rust 侧单元测试覆盖临时文件写入、原子替换和失败清理；浏览器测试覆盖 PDF 用的 HTML（浅色主题、本地图片已内嵌、分页规则存在）。真实生成 PDF 的端到端在 PR 里写手动结果，CI 不要求。
- **C**：
  - 开关和记忆；
  - 停手 1 秒后保存一次、连续输入时 5 秒内至少保存一次（用可控时钟或注入的定时器，不能用固定延时等结果）；
  - 未命名文档不保存；打开不改不写盘；
  - 组词期间不保存，组词结束后保存，上屏文字完整；
  - 保存进行中继续输入，最终磁盘内容包含所有输入、编辑器仍显示“已修改”直到下一次保存完成；
  - 版本冲突时不覆盖、暂停、提示；只读错误只提示一次；
  - 开启时切换文件和关闭窗口不弹询问，保存失败时弹询问；
  - 自动保存不改变焦点、选区、滚动位置，不让编辑区变成 `inert`。
- 不允许用固定延时、重试或放宽断言让测试通过。
