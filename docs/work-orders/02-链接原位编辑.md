## 1. 目标

现状：链接在所见即所得模式里是编辑器的格式标记（link mark），点击后弹出 Crepe 的浮层来改地址。

做完后，按官方 Typora 的实测行为（`docs/typora-acceptance.md`“链接原位编辑（2026-11-10 实测）”一行）：

1. 链接在文档里就是源码字符：`[文字](地址 "标题")` 是一串普通文字，显示层把 `[`、`](地址 "标题")` 藏起来，只显示带链接样式的“文字”。
2. 单击链接不打开，整条展开，光标落在点击处；方括号、圆括号灰色，地址保持链接色带下划线，标题斜体。
3. 方向键能从文字走进地址，地址和标题直接改；光标离开后收起。
4. `<https://…>` 点进去后两侧显示灰色 `<` `>`。
5. Ctrl+单击打开链接；本次运行中第一次单击链接时提示“按 Ctrl + 点击以打开此链接”。
6. 原来的浮层编辑去掉。

## 2. 范围

**做：** 解析结果里 `type === 'link'` 的全部节点，共三种写法，用同一条规则处理：

| 写法 | 例子 | 隐藏的部分 |
| --- | --- | --- |
| 行内链接 | `[文字](地址 "标题")` | `[` 和 `](地址 "标题")` |
| 尖括号链接 | `<https://example.com>`、`<me@example.com>` | `<` 和 `>` |
| 裸网址 | `https://example.com`、`www.example.com`、`me@example.com` | 无（没有标记可藏，只加链接样式） |

裸网址纳入的原因：如果它继续是格式标记，就会和“外来标记写回源码”（4.5）冲突，被改写成 `[网址](网址)`。它在界面上的样子不变，仍显示为链接。

**不做（行为保持现在的样子）：**

- 引用式链接 `[文字][1]`、`[文字]`。**含引用式链接的文档现在会整篇进入源码保护**（原因“此文档的部分结构无法可靠往返转换…”），本单之后必须仍然如此，有测试。
- 图片 `![说明](地址)` 本身。被链接包住的图片 `[![图](a.png)](地址)` 里，图片节点不动，只是它两侧多出隐藏的 `[` 和 `](地址)` 文字。
- 源码模式（CodeMirror）的任何行为，包括它的 Ctrl+K。
- 打开相对路径文件链接（`other.md`）和文内锚点（`#标题`）：Ctrl+单击时只提示“暂不支持打开此类链接”，记进路线图。
- 不改“哪些文档进入源码保护”的规则，不改 `preservedMarkdownBlocks`。

## 4. 设计

### 4.1 读入（`flattenInlineSource`）

对 `type === 'link'` 且自身和首尾子节点都有源文件位置的节点，用和 `strong` 相同的写法还原：

```
pieces(链接起点, 第一个子节点起点) + flatten(子节点) + pieces(最后一个子节点终点, 链接终点)
```

这一条公式同时覆盖三种写法：行内链接得到 `[` + 文字 + `](地址 "标题")`；尖括号链接得到 `<` + 网址 + `>`；裸网址两端长度为 0，只剩文字。

- 没有子节点的链接（`[](u)`）：整段 `pieces(起点, 终点)` 作为文字。
- 缺位置信息的链接：保持现在的做法（留作节点）。
- `linkReference`、`definition`、`image` 不动。
- 做完后，从文件读入的文档里不应再有 link 标记，引用式链接除外（它由内核自带的 `remark-inline-links` 转成标记，文档随即进入源码保护）。

### 4.2 保存

文字已经是源码，沿用 `writeSourceText`，不新增任何转义。必须处理一个现有陷阱：

- `guardLineStart` 里 `firstLine` 的 `/^<\/?[A-Za-z][^<>]*>[ \t]*$/` 会把**独占一段的** `<https://example.com>` 当成 HTML 标签，写成 `\<https://example.com>`。尖括号链接（`<协议:…>` 和 `<邮箱>`）不是 HTML 标签，不得转义。请收紧这条判断，并保证真正的 HTML 标签行（如 `<span>`、`</div>`、`<my-tag attr="1">`）仍被转义，两边都要有单元测试。

除此之外不要改 `guardLineStart` 的其他分支。

### 4.3 语法识别（`inlineSyntaxSpans`）

- `InlineKind` 增加 `'link'`（行内链接）和 `'autolink'`（尖括号链接与裸网址）。
- `link` 的范围：`from/to` 是整条，`innerFrom/innerTo` 是方括号里的文字。另外给出地址和标题在这段文字里的位置（例如 `urlFrom/urlTo`、`titleFrom/titleTo`，标题含两侧引号或括号），以及解析出的 `href`、`title`（取 remark 节点的 `url`、`title`，不要自己解码）。
  - 地址和标题的位置要自己在 `](` 之后扫描：目的地址是 `<…>` 形式或到空白为止的一段（括号可嵌套、可反斜杠转义），标题是 `"…"`、`'…'` 或 `(…)`。是不是链接以 remark 的结论为准，扫描只负责切分；扫描结果和 remark 给的 `url` / `title` 对不上时，放弃细分，把整个 `](…)` 当作一段标记。
- `autolink` 的范围：尖括号写法 `innerFrom/innerTo` 是去掉 `<` `>` 的部分；裸网址 `from === innerFrom`、`to === innerTo`。同样带 `href`。
- 没有子节点的链接（`[](u)`）不生成范围，按普通文字显示。
- 开头的快速排除正则要补上能构成链接的字符，但仍要保持“绝大多数普通段落直接返回”的效果。
- `blockSyntax` 里把范围换算到文档位置时，新增的几个位置字段也要一并换算。
- `blockSyntax` 里对 link 标记补 `[`、`]()` 的现有处理保留（引用式链接和粘贴瞬间仍可能有标记）。

### 4.4 显示（`decorateBlock`）

沿用现有约束：只用 `Decoration.inline`，**光标所在位置不放任何额外 DOM 节点**（输入法会中断，见 `AGENTS.md`）；输入法组词期间不重排装饰。

- 文字部分（`innerFrom..innerTo`）始终包一层 `<a class="md-link">`，带 `href` 和 `title` 属性，`inclusiveStart/End` 与现有格式一致。`href` 的协议是 `javascript:`、`vbscript:`、`data:` 时不写 `href` 属性（改放 `data-href`）。
- 选区没有碰到这条链接时：`[`、`](地址 "标题")`、`<`、`>` 用现有的 `md-marker md-hidden` 隐藏。
- 选区碰到时（规则与加粗相同，贴着边缘也算）：
  - `[`、`]`、`(`、`)`、`<`、`>`：`md-marker`（灰色）。
  - 地址：`md-link-url`，链接色加下划线。
  - 标题（含引号）：`md-link-title`，斜体。
  - 地址和标题之间的空白不加样式。
- 裸网址没有可隐藏的部分，只有 `<a>` 包裹。
- 样式写进 `src/rendered-syntax.css`，颜色用现有主题变量，浅色深色都要对。
- `visibleText`（目录、大纲、脚注预览）应当自动只剩链接文字，用测试确认。

### 4.5 外来的 link 标记写回源码（`dissolveMarks`）

网页粘贴进来的 `<a>` 会带 link 标记。把 link 加入要写回的标记，规则：

- 同一个 link 标记覆盖的连续内容只包一对；link 在最外层，其他格式标记在里面：`[**粗**](地址)`。
- 写法：`[文字](地址)`；有标题时 `[文字](地址 "标题")`，标题里的 `"` 写成 `\"`。
- 地址含空白、控制字符或括号不配对时写成 `<地址>`（里面的 `<`、`>` 用反斜杠转义）。
- 文字里未转义且不配对的 `[`、`]` 加反斜杠。
- 没有标题、文字与地址完全相同、且地址是 `http://`、`https://` 或 `ftp://` 开头的不含空白的网址时，写成 `<地址>`。
- 光标位置的换算沿用现有 `mapOffset` 的思路，粘贴后光标要落在合理位置（链接之后）。

### 4.6 输入与命令

- 删除 `linkInputHandlers` 及其在 `src/editor.ts` 的注册。打出来的字符本身就是链接，不需要输入规则。
- 关闭浮层：`features` 里 `[Crepe.Feature.LinkTooltip]: false`，删掉对应的 `featureConfigs`。
- `format('link')`（Ctrl+K 和“格式 → 链接”）在所见即所得分支改为增删字符，不再创建标记：
  - 选区在同一个文字块内且非空：变成 `[选中文字]()`，光标停在圆括号中间。
  - 选区为空：插入 `[]()`，光标停在方括号中间。
  - 选区完全落在一条已有的行内链接里：不插入，改为选中它的地址部分（方便直接重输）；地址为空时光标放进圆括号。
  - 选区在行内代码里、跨多个块、或落在尖括号链接 / 裸网址里：不做任何事。
  - 施工单 01 的保护（选中 `croquill_raw_block` 时先把光标移到块后的空段落）保留，之后走上面的规则。
- `handleSourceEnter`：光标在行内链接的文字中间按回车，沿用现有通用逻辑，前后两段各自成为完整链接（`[前](地址)` / `[后](地址)`）；`autolink` 不参与这段逻辑。
- `handleSourceArrow`、`toggleInlineSyntax`、`toc-footnotes.ts` 第 69 行的 `kind === 'code'` 判断：确认对新种类无副作用，行为不变。

### 4.7 单击、Ctrl+单击与提示

- 单击链接：光标落在点击处，整条展开（装饰机制自动完成），不导航。
- `MarkdownSurface` 的选项新增两个回调，`src/main.ts` 负责实现：
  - `onOpenLink?: (href: string) => void`
  - `onLinkHint?: (message: string) => void`（`main.ts` 里接到现有的 `toast`）
- Ctrl+单击（macOS 上是 Cmd）落在一条 `link` / `autolink` 的任何部分上：不移动光标、不展开，调用 `onOpenLink(href)`。用点击坐标换算文档位置再查范围，不要依赖点到的是不是 `<a>` 元素（展开后的地址部分不在 `<a>` 里）。
- 普通单击落在链接上：每次程序运行第一次发生时调用 `onLinkHint('按 Ctrl + 点击以打开此链接')`，之后不再提示。
- 输入法组词期间（`event.isComposing` / `view.composing`）不处理 Ctrl+单击。
- 在 `rich-root` 上对 `<a>` 的 `auxclick`（中键）也阻止默认行为，与现有的 `click` 拦截放在一起。

### 4.8 打开外部链接（Rust）

文档可能来自别人，地址不可信。

- `src-tauri/src/lib.rs` 新增命令 `open_external_link(url: String) -> Result<(), String>`，并注册。
- 校验放在一个独立的纯函数里（便于单元测试）：只接受以 `http://`、`https://`、`mailto:` 开头（不区分大小写）的地址；长度不超过 2048；不含空白和 ASCII 控制字符。其余一律返回错误，不打开。
- Windows 上用 `ShellExecuteW`（操作 `open`）交给系统默认程序。给现有的 `windows-sys` 依赖补上需要的 feature（如 `Win32_UI_Shell`、`Win32_UI_WindowsAndMessaging`），**版本号不变**。**不要**通过 `cmd /c start`、PowerShell 或任何会经过命令行解析的方式打开。
- 非 Windows 平台返回“当前平台暂不支持”的错误即可。
- **不新增任何依赖**（包括 `tauri-plugin-opener`、`tauri-plugin-shell`、`url`、`open`）。不放宽 CSP，不改 `capabilities`（如确有必要，在 PR 说明里写明原因）。
- `main.ts` 的 `onOpenLink`：桌面环境下调用该命令，失败时 `toast` 显示原因；地址不是这三种协议时直接 `toast('暂不支持打开此类链接')`，不调用命令。
