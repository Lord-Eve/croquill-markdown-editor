# 施工单 03：安装包与 `.md` 文件关联

- 写单日期：2026-11-15
- 基线：`main`（提交 `4f045ff`，0.6.0 发布之后）
- 分支名：`installer`
- 交付方式：推送分支，向 `main` 开 PR。**不要推送 main，不要合并 PR，不要打标签或发版，不要改版本号。**

开工前先读完仓库根目录的 `AGENTS.md` 和 `acceptance/README.md`。本单与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准，并在 PR 说明里指出冲突。

## 1. 目标

现状：Croquill 只有一个单文件 `croquill.exe`，系统不知道它能打开 `.md`，只能先开程序再打开文件，或者把文件拖进去。

做完后：

1. 多一个安装程序 `Croquill_<版本>_x64-setup.exe`。安装到当前用户，不需要管理员权限，界面是简体中文，带开始菜单快捷方式和卸载程序。
2. 安装后 `.md`、`.markdown` 登记到 Croquill：资源管理器右键“打开方式”里有 Croquill，通过文件关联启动时直接打开那个文件。
3. 卸载后登记清干净，安装前已有的默认打开方式原样恢复，用户文档一个字节都不动。
4. 单文件 `croquill.exe`（便携版）照旧能构建、能用，`build.ps1` 行为不变。
5. 上面 1～3 在 CI 的真 Windows 机器上有自动验收。

## 2. 范围

**做：** Tauri 打包配置、一个新的打包脚本、一个新的安装验收脚本、CI 步骤、文档。

**不做：**

- 代码签名、自动更新、MSI、便携版压缩包。
- 单实例（已打开时再双击第二个文件）。现状是每次启动一个新窗口，保持不变。
- 文件图标另行设计（用程序现有图标）。
- `src/` 下的任何前端代码。本单预期不需要改前端；如果确有必要，先在 PR 说明里写清原因。
- 升级或新增任何依赖（包括 Tauri 插件、single-instance、deep-link）。
- 版本号、标签、发版。

## 3. 现有代码与实测现状（先读懂再动）

| 位置 | 现状 |
| --- | --- |
| `src-tauri/tauri.conf.json` | `bundle.active` 为 `false`，`targets` 为 `"all"`，图标只有 `icons/icon.ico` |
| `build.ps1` | 设好便携工具链环境变量后运行 `npm run tauri -- build --no-bundle` |
| `src-tauri/src/lib.rs` `initial_path` | 取第一个不以 `-` 开头的启动参数，转成绝对路径交给前端 |
| `src/main.ts` 约 349 行 | 启动时调用 `initial_path`，有就打开它，否则恢复上次文档 |
| `.github/workflows/windows-acceptance.yml` | 类型检查、测试、`--no-bundle` 构建、`acceptance/gui-acceptance.ps1` |
| `acceptance/gui-acceptance.ps1` | 键盘驱动的真实窗口验收，证据是窗口标题和文件哈希；脚本只用 ASCII |
| `node_modules/@tauri-apps/cli/config.schema.json` | 本仓库所用 Tauri 版本的配置字段定义。**配置字段名以它为准**，不要凭记忆写 |

写单时在项目所有者的电脑上只读查到的注册表现状（说明真实环境长什么样，也是 5.3 要模拟的情形）：

| 位置 | 值 |
| --- | --- |
| `HKCU\Software\Classes\.md` 默认值 | `md_auto_file`（用户通过“打开方式”选过别的编辑器） |
| `HKLM\Software\Classes\.md` 默认值 | 另一个编辑器的 ProgID |
| `HKCU\...\Explorer\FileExts\.md\UserChoice` | 读不到 |

也就是说：安装程序如果改写 `HKCU\Software\Classes\.md` 的默认值，就会改变这台电脑双击 `.md` 的结果。这件事允许发生，但**必须如实测出来、写进文档，并且卸载时必须恢复原值**。

## 4. 设计

### 4.1 打包配置（`src-tauri/tauri.conf.json`）

- `bundle.active` 改为 `true`，`bundle.targets` 改为只有 `nsis`。
- `bundle.fileAssociations`：一条，扩展名 `md` 和 `markdown`，名称用 `Croquill.Markdown`（它会成为注册表里的 ProgID），描述 `Markdown 文档`，角色为编辑器。
- `bundle.windows.nsis`：安装模式为当前用户；语言只有简体中文；不显示语言选择框。
- WebView2 的安装方式保持 Tauri 默认值，不内嵌离线安装包。
- 补上发布者、简短描述等会显示在“应用和功能”里的字段，内容与 `Cargo.toml`、`package.json` 一致。
- 其余字段（窗口、CSP、标识符 `io.github.lord-eve.croquill`）不动。标识符不变，安装版和便携版才会共用同一份设置。

改完后必须确认两件事并写进 PR 说明：

1. `npm run tauri -- build --no-bundle` 仍然只生成 `src-tauri\target\release\croquill.exe`，不生成安装包。
2. 带 `bundle.active: true` 构建出的 `croquill.exe` 直接运行（不安装）行为和以前一样：现有 `acceptance/gui-acceptance.ps1` 原样通过。

### 4.2 打包脚本（新增 `package.ps1`）

- 放在仓库根目录，写法照 `build.ps1`：同样的便携工具链环境变量处理，脚本内容只用 ASCII。
- 运行 `npm run tauri -- build --bundles nsis`，结束后检查 `src-tauri\target\release\bundle\nsis\` 下确实有一个 `*-setup.exe`，打印它的完整路径、大小和修改时间；没有就以非零退出码结束。
- `build.ps1` 一个字都不改。
- Tauri 首次打包会联网下载 NSIS 工具。下载失败时让错误原样显示出来，不要吞掉，不要加重试。

### 4.3 启动参数

预期不需要改 `initial_path`。请实测并在 PR 说明里写明注册表里实际登记的打开命令（原样贴出），确认下面几种路径通过文件关联都能正确打开：

- 中文加空格：`C:\...\中文 目录\笔记 一.md`
- 文件名含 `&`、`%`、`'`、`(`、`)`
- 扩展名 `.markdown`

如果某一种打不开，原因在 `initial_path` 就修它并补 Rust 单元测试；原因在 Tauri 生成的登记命令就在 PR 说明里写清楚，不要自己手写注册表项去绕。

### 4.4 安装器界面

- 安装、卸载全程简体中文。
- 卸载时如果有“删除应用数据”的选项，默认不勾选；静默卸载不删除应用数据（最近打开列表等设置留着）。
- 不自定义 NSIS 模板、不加安装钩子脚本。Tauri 默认行为不满足本单某一条时，先在 PR 说明里提出，不要自行引入自定义模板。

## 5. CI 自动验收

### 5.1 工作流（`.github/workflows/windows-acceptance.yml`）

在现有步骤之后追加，现有步骤的命令和顺序不变：

1. 构建安装包：`npm run tauri -- build --bundles nsis`。
2. 定位 `*-setup.exe`，输出路径、大小。
3. 运行新脚本 `acceptance/installer-acceptance.ps1`。
4. 把安装包和本脚本的输出加进现有的 artifact 上传（`if: always()`）。

### 5.2 脚本要求（新增 `acceptance/installer-acceptance.ps1`）

- 只用 ASCII，中文路径和标题字符用码点拼出，做法照 `gui-acceptance.ps1`。可以复用其中找窗口、读标题的写法，但**不要修改 `gui-acceptance.ps1`**。
- 证据只认：注册表值、磁盘文件及其 SHA256、进程的可执行文件路径、窗口标题。结果写 `results.json` 和 `report.md`，每一步保留截图。
- 等待一律用“轮询某个条件直到成立，超时即失败”，超时时间可以宽，但不得用固定延时代替条件，不得失败后重试整步。
- 任何一步失败，脚本以非零退出码结束；结束前无论成败都尽力卸载并结束它启动的进程。

### 5.3 必过项

安装前准备：

1. 记录 `HKCU\Software\Classes\.md`、`.markdown` 的默认值（可能不存在），以及 `FileExts\.md\UserChoice` 是否存在。
2. 模拟“用户已经有别的默认程序”：安装前把 `HKCU\Software\Classes\.md` 默认值写成一个测试用的假 ProgID（例如 `CroquillTest.Prior`）。`.markdown` 不预先写，覆盖“原来没有值”的情形。

静默安装（`/S`）：

3. 安装程序退出码为 0，全程不出现 UAC 提示（不以管理员身份启动它）。
4. 安装目录在当前用户目录下，里面有 `croquill.exe` 和卸载程序。
5. “应用和功能”登记存在（`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\` 下），显示名称为 Croquill，版本号等于 `tauri.conf.json` 的 `version`。
6. 开始菜单里有 Croquill 快捷方式，指向安装目录的 `croquill.exe`。
7. `HKCU\Software\Classes\Croquill.Markdown` 存在，打开命令指向安装目录的 `croquill.exe` 并带 `%1`。
8. `.md`、`.markdown` 都登记了 Croquill（把实际写入的键和值全部记进 `results.json`）。
9. 记录安装后 `HKCU\Software\Classes\.md` 的默认值：是否从假 ProgID 变成了 `Croquill.Markdown`。**这一条只记录不判定**，结果要写进 `report.md` 和文档（见第 7 节）。

通过文件关联打开：

10. 准备 4.3 列出的三类文件（内容含中文，CRLF 和 LF 各一份，带 BOM 一份），记下 SHA256。
11. 取第 7 条登记的打开命令，把 `%1` 换成文件路径后执行：出现的窗口属于安装目录的 `croquill.exe`，标题以该文件名开头且没有未保存标记。三类文件各做一次。
12. 用系统的“打开”动作启动 `.md` 文件（`Start-Process -FilePath <文件>`）。当且仅当第 9 条记录到默认值是 `Croquill.Markdown` 且 `UserChoice` 不存在时，这一条必过，判据同第 11 条；否则记录实际被启动的程序并标注为“未判定”，写明原因。
13. 第一个窗口不关，再用同样方式打开第二个文件：出现第二个窗口，两个窗口标题各自对应自己的文件。
14. 关闭全部窗口后，三类文件的 SHA256 与第 10 条一致。

静默卸载：

15. 卸载程序退出码为 0。
16. 安装目录、“应用和功能”登记、开始菜单快捷方式、`HKCU\Software\Classes\Croquill.Markdown` 都不存在了。
17. `HKCU\Software\Classes\.md` 默认值恢复为第 2 条写入的假 ProgID；`.markdown` 回到安装前的状态（没有指向 `Croquill.Markdown` 的残留）。
18. 测试文档仍在，SHA256 不变。
19. 脚本结束前清掉第 2 条写入的假 ProgID，把注册表还原到第 1 条记录的状态。

如果 Tauri 默认的安装器做不到第 17 条，**不要改判据**，在 PR 说明里写出实测到的值，等审核意见。

- `acceptance/gui-acceptance.ps1` 不改，原样通过。
- 不得用放宽断言、固定延时、重试来让验收通过。CI 上与本单无关的老测试偶发超时不属于本单，写在 PR 说明里即可，不要为它改测试。
- `build.ps1`、`start.ps1`、`clean.ps1`、`clean-all.ps1` 不改。
- 不提交 `examples/private/` 下的任何文件，不读取其内容。
- 不提交 `src-tauri/target/` 下的任何产物（安装包也在其中）。
- 不运行 `clean.ps1` / `clean-all.ps1`。不升级任何依赖。
- **不要在开发机上运行安装程序**，也不要手动改开发机的注册表。安装、卸载只在 CI 上做；本机真实安装由 Claude 在合并前验收。
