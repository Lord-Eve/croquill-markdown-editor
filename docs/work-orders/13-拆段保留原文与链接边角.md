## 4. 设计要求

### A. 回车拆段

光标在一段的中间或行尾，按回车把它拆成两段，或在段末回车新增一段（包括引用、提示块、列表项里的段落）。在列表项里回车新建列表项的写法不在本单范围，保持现状。

> **第 2 轮修订（2026-11-27，审核 PR #17 后）。** 写单时我把“行尾回车后新段开头留着一个换行”当成了正确行为，第 3 节探测表和本节第 2、4 条原来的例子都建立在这个前提上，这是写单的错误。官方 Typora 1.14.15 本机实测：`>甲↵>乙↵>丁↵` 在“甲”行尾按回车，源码立即变成 `>甲↵>↵>乙↵>丁↵`，新段从“乙”开始，光标停在“乙”前；普通段落 `戊↵己↵庚↵` 在“戊”行尾按回车，得到 `戊↵↵己↵庚↵`。下面的第 0 条和改过的例子以此为准。

0. **拆分点上的换行被吃掉（Typora 实测）。** 光标正好在一行末尾（后面紧跟段内换行）时按回车，这个换行不进入任何一段：前一段到上一行末尾为止，新段从下一行的第一个字开始，光标停在新段开头。光标正好在一行开头（前面紧跟段内换行）时同理，吃掉前面的那个换行。被吃掉的如果是硬换行，连同它的写法（两个空格或反斜杠）一起去掉（这一点按同一规则推断，Typora 未单独实测）。按回车之后、还没输入任何字时，文档就必须是正确的结果，不能出现 `<br />`，不能改写原有行；停手自动整理或按 Ctrl+S 保存的也是这个结果。
1. **原有行逐字节不变。** 光标后面整行被带进新段的那些行，保存时和原文那一行完全相同：引用标记（`>` 或 `>␣`、嵌套的 `>>`、`>␣>`）、懒续行、行首缩进、行尾硬换行的写法（两个空格、反斜杠）都保留，换行符（LF / CRLF）也保留。
2. **新增的行跟随所在引用的写法。** 拆段新增的分隔行，以及光标在行中间拆开时新段的第一行，引用标记照抄光标所在那一行的标记：`>甲乙↵>丁↵` 在“甲”后按回车，结果是 `>甲↵>↵>乙↵>丁↵`；`>␣甲↵>乙↵` 在“甲”行尾按回车，结果是 `>␣甲↵>↵>乙↵`（“乙”这一行原样带过去）；单行的 `>甲↵` 在段末回车并输入“丙”，结果是 `>甲↵>↵>丙↵`。分隔行只写标记本身，不带行尾空格。不在引用里的段落，新增行按现有默认写法。
3. **光标在一行中间时**，这一行被分成两半：前一半留在原行，原行的标记和缩进不变；后一半成为新段第一行，按第 2 条处理。
4. **硬换行跟着它所在的行走**：不在拆分点上的硬换行，随所在的行进入哪一段都保留原来的写法。例如 `甲↵乙␣␣↵丁↵` 在“甲”行尾按回车，结果是 `甲↵↵乙␣␣↵丁↵`。
5. 被拆开的段落前后的其他块、同一引用里没碰过的其他段落，按施工单 10 的规则逐字节不变。
6. 拆段后一次 Ctrl+Z 恢复原文（逐字节），光标回到原处。
7. 拼出来的写法必须经过现有的结构等价检查（`hasEquivalentMarkdownStructure` 和 `accept`）才能采用；检查不通过时退回现在的写法，**绝不能丢字或改变结构**。PR 里列出会退回的情况。
8. 输入法组词中的回车不触发拆段（底线第 3 条，现状如此，不要改坏）。

### B. Ctrl+单击链接的边角

**基准：编辑器里 `#片段` 跳到的标题，必须是导出 HTML 里 `id` 等于该片段的那个标题。** 导出的规则是：文档里所有层级的标题（含列表、引用、提示块里的，含源码保护块里的）按文档顺序依次分配 ID，自定义 ID 优先，重名加 `-1`、`-2` 后缀。文档里有带 `id` / `name` 的 HTML 元素时导出会让标题避让这些 ID，本单不要求对齐这种情况，PR 里写明。

1. **B1 匹配顺序。** `matchHeading` 先按实际分配的 ID 匹配，再按自定义 ID、标题文字、Typora 写法（小写、空格换 `-`、去标点）依次兜底。例：`# 甲↵↵# 乙 {#甲}↵`，`#甲` 跳到“甲”，`#甲-1` 跳到“乙”。施工单 12 里已有的匹配用例（标题文字、自定义 ID、重名、Typora 写法、找不到）结果不变。
2. **B2 源码保护块里的标题。** 正文模式下，源码保护块里的标题参与 ID 分配和匹配。匹配到时把该源码保护块滚入可见范围，光标放在该块前后均可，PR 写清选了哪种；不要求定位到块内的具体行。保护块后面的同名标题按全文顺序编号。块级 HTML（`kind` 为 `html` 的块）里的标题不算。
3. **B3 源码模式。** 当前处于源码模式时（例如打开的文档整篇进入源码保护），列表、引用、提示块里的标题也参与匹配，跳到该标题所在行的行首并滚到顶部。**大纲仍只列顶层标题**，不要改 `markdownOutline` 和大纲跳转；为此另取一份全部层级的标题列表。
4. **B4 块级 HTML 里的链接。** 渲染后的块级 HTML 里，Ctrl+单击 `<a href>`：
   - 地址交给与行内链接相同的 `onOpenLink`，外部链接、本地 Markdown、其他文件、`#标题` 的处理和提示与施工单 12 完全相同；
   - 不进入源码编辑；
   - 按住 Ctrl 指向这类链接时显示手形光标，规则与施工单 12 第 4 节 C 相同（不动鼠标、按下或松开 Ctrl 立即切换，失去焦点恢复，组词中不切换）；
   - 普通单击照旧进入原位源码编辑，`<details>` 的 `<summary>` 照旧展开折叠；
   - 地址取经过 `html-sanitize.ts` 过滤后的 `href`。被过滤掉地址的链接不打开，也不显示手形光标。
   - 官方 Typora 对这一点没有实测（本机试用已过期），按行内链接的规则做。
