## 4. 设计

### 4.1 大纲跟随

**高亮哪一项（两种模式同一规则，依据 Typora 实测）：**

1. `#editor-scroll` 可视区里露出来的标题中最靠上的那个。标题块和可视区有重叠就算露出来。
2. 可视区里一个标题都没有时，取可视区上方最近的那个标题。
3. 可视区在第一个标题之前且没有标题露出来时，不高亮任何项。

只算进了大纲的标题（顶层标题，不含 HTML 块里的）。源码模式用标题所在行的位置按同一规则计算。

**什么时候更新：** 正文滚动、文档内容变化后大纲重建、切换模式、窗口或侧栏尺寸变化、侧栏切到“大纲”标签。滚动中的更新要节流，可以用 `requestAnimationFrame`，不得用定时轮询。

**其他要求：**

- 重建大纲后，高亮项、折叠状态、大纲列表自己的滚动位置都要保持。怎么做（局部更新还是重建后恢复）由你定。
- 点击大纲项：高亮立刻落在被点的那一项。所见即所得是平滑滚动，滚动途中高亮不得在中间各项之间跳动。文末的标题滚不到顶部时，被点的项也要保持高亮，直到用户自己再滚动或编辑，之后恢复按规则计算。
- 高亮项变化后，如果它不在大纲列表的可见范围内，把它滚进来（就近对齐）。不得抢走正文的焦点。
- 高亮项加 `aria-current="true"`，样式沿用现有 `.active`。
- 大纲项与正文标题现在靠序号对应。请确认原文保护块、HTML 块、引用和列表里的标题不会让两边的序号错开；发现会错开的情形，修掉或在 PR 说明里如实写出。

### 4.2 大纲折叠

- “下级”的定义：某一项之后连续的、级别数字比它大的项，直到遇到级别小于等于它的项为止。跳级（一级标题后面直接是三级）也算下级。
- 有下级的项，文字左边显示一个小三角。三角是独立的按钮：带 `aria-expanded` 和中文 `aria-label`（“折叠”/“展开”），可用 Tab 聚焦，Enter 和空格切换。点三角只折叠或展开，不跳转；点文字只跳转，不改变折叠状态。
- 没有下级的项留出同样宽度的空位，各级文字的缩进对齐不乱。
- 折叠一项会隐藏它的全部下级。再展开时，各下级恢复它们自己原先的折叠状态。
- 当前位置对应的项被折叠隐藏时，高亮落在它最近的、看得见的上级项上。
- 跳转（点击大纲项）不自动展开任何项。
- 折叠状态只放在内存里，跟着当前文档走：编辑导致大纲重建时保留；打开另一个文档、新建文档后清空。同名标题要能区分（例如用级别、文字和它是第几个同名项来识别）。标题改名后该项的折叠状态丢失可以接受。
- 样式只用现有主题变量，浅色和深色都要能看清。大纲标签上的标题总数照旧显示全部标题数。

### 4.3 切换模式保留位置

**光标（依据 Typora 实测：切换后光标落在同一个字后面）：**

- 必须精确到字的情形：光标在段落、标题、列表项、任务列表项、引用里的段落中，位于普通文字或行内格式标记字符之间。两个方向都要成立（所见即所得→源码，源码→所见即所得）。
- 允许退到“这一块的开头”的情形：表格、代码块、公式、HTML 块、原文保护块、图片块、文首元数据、脚注定义、目录块，以及任何你算不准的位置。
- 硬性要求：**宁可退到块开头，也不能落进别的块。** 映射出的位置所在的块必须和切换前光标所在的块是同一块内容。请在 PR 说明里写清你怎样判断“算得准”，这个判断必须是确定性的，不能靠猜测加兜底。
- 切换前有非空选区时，按选区的活动端（head）映射，切换后是一个光标。
- 文档因为进入源码保护而留在源码模式的情形，不在本单要求之内。

**滚动（依据 Typora 实测：光标所在行切换前后在屏幕上的高度基本不变）：**

- 光标在可视区内：切换前后，光标所在行的顶边相对于窗口顶部的位置相差不超过 24 CSS 像素。提示条显示或隐藏时使用同一参照。目标超出可见或可滚动范围时对齐到最近的可达位置。
- 光标不在可视区内（用户滚走了）：光标仍按上面的规则映射到它原来的位置，不把它拉进屏幕；滚动改为按可视区顶部第一个露出来的块对齐，该块在另一种模式里对应内容的顶边同样相差不超过 24 CSS 像素。
- 恢复滚动必须等布局完成后做，可以用 `requestAnimationFrame` 或 `ResizeObserver`，不得用固定毫秒的延时。

**不能改变的行为：**

- 切换本身不产生撤销步骤，不触发内容变化通知，不把文档标成已修改。
- 没有编辑过的文档，来回切换任意次后 `getMarkdown()` 仍与原文逐字节一致（BOM、CRLF、LF 都要覆盖）。
- 不得为了映射位置去修改序列化结果，不得往文档里插入任何标记字符或节点。光标所在位置不能放额外的 DOM 节点（见 `AGENTS.md`）。
- 输入法组词期间不切换（现有行为）。`deferFocus()`、`focus()` 的现有逻辑和查找栏的现有行为不变。

### 4.4 安装验收脚本的三个小项

1. `acceptance/installer-acceptance.ps1` 判断“用户是否已经固定了默认程序”时，除了 `FileExts\.<扩展名>\UserChoice`，再看同一位置下的 `UserChoiceLatest`（Windows 11 的新位置）。把 CI 机器上这两处的实际结构记进 `results.json`。`README.md`“设为默认打开方式”一节改成不提注册表项名的说法：用户在系统里选过默认程序时，安装不会改变双击的结果，需要手动选一次。
2. 这个脚本会写测试用注册表值并卸载已安装的 Croquill。加一道保护：环境变量 `CI` 不是 `true`、又没有传显式开关（例如 `-AllowLocalRun`）时，在做任何注册表写入、安装或卸载之前就以非零退出码结束，并打印一句英文说明。工作流文件不需要为此改动。
3. 场景 D 在 `.markdown` 安装前已有默认值的机器上会被跳过。跳过时在 `results.json` 和 `report.md` 里留一条记录，写明“跳过”和原因，不计为失败。

脚本内容继续只用 ASCII。这三项不得改动现有 27 项的判据。

## 5. 测试要求

用仓库现有的浏览器测试方式（`tests/harness.html`、`tests/harness.ts`、`tests/app-*.test.ts`）新增测试，不修改现有测试的预期。

**大纲（至少覆盖）：**

1. 一份多章节长文，滚动到若干位置，断言高亮项符合 4.1 的三条规则（含“屏幕顶部是上一节正文、下面露出下一节标题”的情形）。
2. 源码模式下同样的断言。
3. 在正文里打字导致大纲重建后，高亮项和折叠状态不变。
4. 点击大纲项后高亮落在该项；点击文末滚不到顶部的标题后，高亮仍是该项；用户再滚动后恢复按规则计算。
5. 折叠、展开、嵌套折叠后再展开上级，各下级的状态正确；`aria-expanded` 正确；键盘可操作。
6. 当前项被折叠隐藏时，高亮落在看得见的上级。
7. 同名标题各自的折叠状态互不影响；跳级标题的下级判定正确。
8. 打开另一个文档后折叠状态清空。

**切换位置（至少覆盖）：**

1. 样本包括：含加粗、斜体、行内代码、链接、高亮的中文段落；各级标题；嵌套列表与任务列表；引用里的段落；段内软换行和硬换行；带文首元数据的文档；CRLF 文档；带 BOM 的文档。
2. 每个样本取多个光标位置（块首、块尾、标记字符内侧和外侧、中文字之间）。所见即所得→源码：断言源码光标的偏移等于预期值，预期值在测试里用文档中唯一的标记串算出。源码→所见即所得：断言光标所在的块和块内偏移。
3. 往返：所见即所得→源码→所见即所得，光标回到原位置。
4. 4.3 列出的退化情形：断言光标落在该块开头，且没有落进别的块。
5. 滚动：光标在可视区内和不在可视区内两种情形，分别断言 24 CSS 像素的要求。
6. 不变式：未编辑文档来回切换多次后正文与原文一致、未被标成已修改、撤销历史没有多出步骤。
