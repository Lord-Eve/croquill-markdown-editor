## 4. 设计要求

### A. 网页格式（`text/html`）

1. **共用导出的渲染。** 把 `export-document.ts` 里从语法树到 DOM 的同步渲染抽成一个共用函数，导出和复制都调用它。**导出 HTML 和 PDF 的结果不能变**（现有导出测试全部原样通过）。不要另写一套 Markdown 到 HTML 的转换。
2. **复制必须同步写好剪贴板。** 复制事件里不能等待异步操作。图片不读取、不转 data URL，按原地址写出。
3. **内容：**
   - 行内：加粗、斜体、删除线、行内代码、高亮、行内链接（`<a href>`）、尖括号链接和裸网址、行内 HTML（经 `html-sanitize.ts` 过滤，同导出）；转义和实体显示成实际字符。
   - 块：标题（不带 `{#id}` 等属性文字）、段落、段内换行、有序 / 无序 / 任务列表、引用、提示块、表格、代码块、分割线、公式（沿用导出的 MathML）、脚注。
   - 不出现：任何标记字符、标题属性、作者注释（`<!-- -->`）、`data-pm-slice` 以外的编辑器内部属性和类名。
4. **样式内联。** Word 和微信会丢掉 `<style>` 里的样式，下面几项用元素自身的 `style` 属性写出，其余靠标签本身：
   - 行内代码和代码块：等宽字体、浅灰底色；
   - 高亮：浅黄底色；
   - 表格：单元格有细边框，表头加粗；
   - 引用：左侧竖线、灰色文字。

   **不论当前是浅色还是深色主题，复制出去都按浅色写**，不写死白色文字或深色底色。
5. **部分选区。**
   - 只复制选中的部分。
   - 选区两端落在某个行内格式里时（例如只选了“粗”字，或从加粗中间开始选），复制出去的那部分仍带这个格式，不出现落单的 `**`。可以先用 `sourceEnterMarkers` 的思路在两端补齐标记，再渲染。
   - 选区跨多段时，段落结构保留。
   - 只选了表格的几个单元格时，按表格写出选中的单元格。
6. 原文保护块（灰色等宽原文）按导出的写法（`<pre>`）写出。

### B. 纯文本（`text/plain`）

与现在一致：选中内容的 Markdown 源码。本单不改。

### C. Croquill 内部复制粘贴保持原写法

在 Croquill 里复制、再粘贴到 Croquill（同一文档或另一个窗口），粘贴结果必须和现在一样：源码字符逐字不变，例如 `__粗__` 不会变成 `**粗**`，`<span style="color:red">` 原样保留，标题的 `{#id}` 不丢。

改了 `text/html` 之后，Milkdown 的粘贴可能改用网页格式解析，这就会改写原写法。必须保证内部粘贴仍走原来的路径，例如在剪贴板里另放一份 ProseMirror 能识别的原文切片，或在粘贴时识别出这是 Croquill 自己复制的内容。具体做法由你决定，PR 里写清楚。

### D. 剪切

Ctrl+X 写入剪贴板的内容与复制相同；文档里删除选区的行为不变，一次撤销恢复。

### E. 不能打断输入法

复制、剪切只在用户触发时运行，不在组词过程中做任何事（底线第 3 条）。

1. 浏览器测试（参考 `tests/app-heading-keys.test.ts` 的写法）：在所见即所得模式设置选区，向编辑区派发 `copy` 事件（`new ClipboardEvent('copy', { clipboardData: new DataTransfer() })`），读取 `text/html` 和 `text/plain` 断言。覆盖：

   - 作者注释不出现；

   - 深色主题下复制，网页格式里没有白色文字。
2. 部分选区：只选加粗里的一个字；从加粗中间选到普通文字；跨两段；表格里选两格。
3. 纯文本：与改动前完全相同（取几个代表性选区，把期望值写死在测试里）。
4. 内部粘贴：把复制得到的 `DataTransfer` 原样派发给 `paste` 事件，粘贴到另一个位置，断言 `getMarkdown()` 的完整结果。覆盖 `__粗__`、`*斜*` 与 `_斜_`、`<span style="color:red">红</span>`、`# 标题 {#id}`、表格、多段引用。
5. 剪切：剪贴板内容与复制相同，文档删除选区，一次 Ctrl+Z 恢复。
6. 导出：现有导出测试全部原样通过，不改期望值。
