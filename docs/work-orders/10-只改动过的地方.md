## 1. 目标

官方 Typora 保存时只改用户动过的那几行，其余字节不变。Croquill 要做到一样。

| 项 | 现在（2026-11-21 在 `main` 实测） | 做完以后 |
| --- | --- | --- |
| A. 没碰过的块 | 下面几种情况会把全文重写：改代码块里的字；段首退格合并两段；文档不超过四个顶层块时任何修改。重写会把 Setext 标题改成 `#`、紧凑表格 `\|甲\|乙\|` 加空格对齐、`\| --- \|` 改成 `\| -- \|`、缩进代码块改成围栏代码块、`*` 列表改成 `-`、去掉段首缩进、合并多个空行、在文件末尾补换行 | 不管做什么修改、文档多短，没碰过的块、块与块之间的空行、文件末尾有没有换行，都和原文逐字节一致 |
| B. 改到的那一块 | 改表格某一格，表头行也被重新对齐（`\| 地点 \| 距离 \|` → `\| 地点  \| 距离  \|`）；改列表某一项，整个列表的 `*` 变成 `-`；改 Setext 标题变成 `#` 标题 | 只改动过的行变；同一块里没动的行、列表符号、代码块的围栏或缩进写法、标题的写法都保留 |

普通段落、ATX 标题、引用里改字，回车分段，Shift+Enter，现在已经只改那一处（`src/local-markdown.ts`），不能变差。

## 2. 范围

做：A、B 两项，测试，一份公开手动验收样本，文档和构建。

不做：

- 段首按退格时，段落被并进上方代码块的编辑行为（实测会发生，这是编辑行为，不是保存问题，已记入路线图另做）；
- 新插入的有序列表项怎样编号：照相邻项的写法即可，不做额外规则；
- 源码模式的保存（源码模式本来就是原文）；
- 依赖升级或新增依赖。

## 4. 设计要求

具体做法由你决定，但必须满足：

1. **没碰过的顶层块原样写回。** 任何一次整理（局部或全文）的结果里，内容和类型都没变的顶层块，要使用它上次写出时的原文字节。两个都没碰过的相邻块之间的空白（空行数、缩进）也照原文。改动的块与相邻块之间的分隔，按原文已有的写法，原文没有可参照的再用默认写法。
2. **改到的那一块只改动过的行。**
   - 表格：只重写内容有变化的行；其他行、分隔行、对齐写法不动，不重新加空格对齐。新增的行沿用相邻行的写法。
   - 列表：保留原来的符号（`*`、`+`、`-`）和有序列表的分隔符（`.` 或 `)`）、起始编号写法、缩进宽度；没动的项原样保留。
   - 代码块：围栏代码块保留围栏字符（反引号或 `~`）、长度和信息串；缩进代码块保持缩进写法。只有内容行变化。
   - 标题：Setext 标题保持 Setext 写法（下划线行可以原样保留），ATX 标题保留原来的结尾 `#`。
   - 段落：没动的行保留原来的段首缩进、硬换行写法（反斜杠或行尾两个空格）。
   - 数学块、引用、提示块里的内容同理：只改动过的行变。
3. **文件末尾**：原文末尾有没有换行、有几个，保存后保持不变；最后一块被修改时也一样。
4. **四块以内的特例删掉**（`src/local-markdown.ts` 第 73–76 行）。短文和长文保存结果一致。
5. **安全兜底不变。** 拼出来的结果必须重新解析后与编辑器里的文档完全一致，才能作为保存结果；对不上时退回现在的全文写出。任何情况下都不能丢字或写出与编辑器不一致的内容。退回全文写出的情况在 PR 里列出。
6. **不变慢。** `npm run perf` 的停手整理时间不能比 `main` 明显变慢（PR 里贴前后两组数字）。长文按一个键不能多做全文序列化。
7. 打开后没改的文档保存仍逐字节一致；改了又撤销回原样，仍逐字节一致；BOM、CRLF 保持不变。

6. 一个兜底用例：构造拼接结果与编辑器内容不一致的情况，确认退回全文写出，内容不丢。
