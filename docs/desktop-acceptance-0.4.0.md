## 本轮发现并修复

**表格正文单元格里的脚注上标点击后不跳转。** 表头单元格和正文段落里的正常。原因：表格组件在鼠标按下时安排了“下一帧选中这个单元格”，它在点击之后执行，把跳转后的光标又拉了回来。修复：脚注上标自己接管按下和点击，不让按下事件传到表格组件。新增两条浏览器回归（表格正文单元格、表头单元格），修复前前者失败，修复后都通过；点击不改动文档内容。重建 exe 后在真实窗口复验：点击表格里的上标 `1` 跳到定义，光标落在定义内，标题栏没有未保存圆点。

同一轮全量测试里，`tests/app-heading-keys.test.ts` 的“标题内普通退格”一条偶发失败。追踪结果是测试时序：编辑器取得焦点后的 200 毫秒内，ProseMirror 会把“光标跳到文档最开头”当作浏览器异常并还原，测试在这段时间内对首行按 Home 就被撤回。改为等这个窗口结束、并在每次按键后等编辑器模型选区到位；连续 5 次运行全部通过。产品代码未改。

## 观察到但本轮不改

- 编辑文档任何一处后保存，文档里其他“普通表格”（不含 `<br>`、行内原文片段或高亮）的分隔线和列宽空白会被重新对齐。本轮在 `highlight-alert.md` 的八列表格上看到。这是路线图“保留更多原有 Markdown 写法”里的已知限制，内容不丢，只是空白变化。
- 深色主题下，独占一行和多行的 HTML 注释淡得接近看不清。
- 窗口很窄时八列表格每列只剩一个字宽，没有溢出，但不好读。
- 撤销分组：连续两步操作间隔很短时会合并为一步撤销（内核默认行为）。

## 没有覆盖

真实中文输入法下的目录、脚注操作；从资源管理器拖入 `.md`；最近打开与启动恢复的手动复查（CI 的 `restart-restore`、`restart-blank` 已覆盖启动恢复）。
